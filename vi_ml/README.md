# vi_ml — 価値反復の CNN サロゲート

`vi_lib` の u64 ソルバ（`bench_map`）を教師にして、占有格子＋ゴールから
θ 最小の価値場（秒）を U-Net で回帰し、貪欲降下で経路が出るかを測る。

```
cd vi_ml && uv sync                 # 初回のみ（torch CPU 版）
make ml-data                        # bench_map を build → 64² を 4000 枚、128² を 600 枚解いて out/*.npz
make ml-train                       # U-Net 学習 → out/unet.pt
make ml-eval                        # 値誤差・到達率・経路長比・時間、続けてピラミッド走行
make ml-test
```

| ファイル | 役割 |
|---|---|
| `vi_ml/maps.py` | 地図生成: 部屋＋廊下(BSP) / 迷路 / ブロブ / tb3_house の切り出し。壁は `thicken` で 1 セル膨張（VI は遷移先セルしか見ないので 1 セル壁は 3 セル前進に抜けられる） |
| `vi_ml/vi.py` | PGM+YAML を書いて `bench_map --dump-value` を呼ぶ。セル 0.1 m、safety 0.2 m / 30 s、`frontier2d_sparse` |
| `vi_ml/dataset.py` | 上 2 つを回して `.npz`（free, goal, value, solve_ms, kind） |
| `vi_ml/model.py` | 4ch 入力（free, goal, 境界値, 境界マスク）→ log 正規化した値場の U-Net。境界 ch は窓モード用 |
| `vi_ml/rollout.py` | 半径 3 セル・見通し付きの貪欲降下（真の値場で 100/100 到達） |
| `vi_ml/train.py` | 64² 全体 ＋ 128² から切った 64² 窓（境界 2 セルに真値）を混ぜて学習 |
| `vi_ml/eval.py` | 保留 400 枚で U-Net vs 厳密解 |
| `vi_ml/diffusion.py` | 条件付き拡散モデル（同じ U-Net 本体に x_t と t/T を 2ch 追加、x0 予測、DDIM η=0 で生成）。`make ml-train-ddpm` / `ml-eval-ddpm` |
| `vi_ml/policy.py` | 方策ヘッド: 各セルの最良ジャンプ (dy,dx)∈[-3,3]² を 49 クラス分類。`make ml-train-policy` / `ml-eval-policy` |
| `vi_ml/warmstart.py` | `bench_map --init-value` で CNN の場を初期値にした厳密 VI と cold の比較 |
| `vi_ml/pyramid.py` | 128² を 2× プールした粗場を CNN で出し、ロボット周辺の 64² 窓の境界に流し込んで細場を CNN で出し、8 歩進んで窓を動かす |

## 結果（2026-09-03、U-Net 4.4M、25 エポック、val L1 0.013、CPU 1 スレッド）

保留 400 枚の 64²（`make ml-eval` 前半）:

|---|---|---|---|---|---|---|---|
| blobs | 94 | 0.605 | 0.577 | 1.000 | 1.01 | 25.5 | 43.8 |
| crop | 78 | 0.071 | 0.835 | 1.000 | 1.02 | 24.9 | 36.5 |
| maze | 72 | 0.201 | 0.253 | 1.000 | 1.05 | 25.8 | 139.2 |
| rooms | 156 | 0.229 | 0.346 | 0.990 | 1.02 | 25.9 | 76.5 |
| all | 400 | 0.281 | 0.479 | 0.996 | 1.02 | 25.6 | 59.6 |

保留 100 枚の 128² × 4 始点のピラミッド走行（後半）:

| kind | runs | success(pyramid) | success(true greedy) | len ratio | pyramid ms | vi ms |
|---|---|---|---|---|---|---|
| blobs | 100 | 0.480 | 1.000 | 1.04 | 106 | 97 |
| crop | 100 | 0.450 | 1.000 | 1.04 | 135 | 116 |
| maze | 76 | 0.013 | 1.000 | 1.11 | 135 | 1061 |
| rooms | 124 | 0.411 | 1.000 | 1.06 | 143 | 224 |
| all | 400 | 0.362 | 1.000 | 1.05 | 132 | 173 |

読み方: 値の相対誤差は小さい（crop 7 %）のに貪欲降下の到達率が 48 % で、失敗は全て局所最小（歩数上限に当たった例はゼロ、詰まった点の真値の中央値は 135 s でゴールから遠い）。
つまり場の大まかな形は合っていて、小さな凹凸が降下を止めている。時間は 64² で CNN 26 ms 対 VI 60 ms、ピラミッドは 132 ms 対 173 ms で、この大きさでは速度の勝ちもない。迷路は 1 % で、受容野の限界がそのまま出ている。

種類別（all 行のみ抜粋、元表は `out/eval_ddpm*.md`）:

```
| all | 400 | 4.420 | 0.514 | 0.996 | 1.00 | 128.0 | 55.7 |
```

読み方: 到達率は回帰と同じ 50% 前後で頭打ちで、ステップを増やしても上がらない。値の相対誤差は桁で悪く（クランプした log 値を戻すので外れ値が大きい）、推論は最短でも 5 倍遅い。局所最小はサンプリングの多様性では消えず、この問題では拡散モデルを使う理由はない。

## 内蔵 Radeon での学習（2026-09-13、torch-directml）

`uv sync` で `torch-directml` が入り（torch は 2.4.1+cpu に固定される）、`model.device()` が Radeon 780M を自動で選ぶ。`VI_ML_DEVICE=cpu` で無効化。推論は batch=1 では CPU の方が速いので CPU のまま。

## 方策ヘッド（2026-09-13、保留 400 枚・8 始点、GPU 25 エポック、val CE 0.52）

値場ではなく、真の値場に対する貪欲降下（半径 3 セル・見通し付き）が各セルで取るジャンプをラベルにして分類した。走行はロジット順に見通しの通る最初のジャンプを取る。オラクル（真ラベル）の走行は貪欲降下と 400/400 で同一経路。

| kind | n | jump acc | success(policy) | len ratio | policy ms | vi ms |
|---|---|---|---|---|---|---|
| blobs | 94 | 0.592 | 0.992 | 0.99 | 18.6 | 44.9 |
| crop | 78 | 0.761 | 0.997 | 1.00 | 28.5 | 41.1 |
| maze | 72 | 0.900 | 0.852 | 1.00 | 19.5 | 145.6 |
| rooms | 156 | 0.582 | 0.992 | 1.00 | 20.6 | 80.1 |
| all | 400 | 0.677 | 0.968 | 1.00 | 20.9 | 68.2 |

読み方: 値回帰の到達率 48 % が 97 % になり、経路長比は 1.00。迷路も 25 % → 85 %。値に頼らないので局所最小が存在せず、失敗はループ（歩数上限）だけになる。ジャンプ精度 68 % が到達率より低いのは同値のジャンプが複数ある（ラベルはその先頭）ためで、どれを取っても経路は縮む。推論 21 ms は VI の 54 ms より速いが、64² ではまだ差が小さい。

## warm start（2026-09-13、保留 50 枚、frontier2d_sparse、反復上限 2000）

`bench_map --init-value` を追加し、θ 最小の 2D 場を全 θ の初期値にして解いた。`seed_frontier_2d` が有限値のセルを全部フロンティアに入れるので、ソルバ側の改造は不要。

| init | iters (median) | updates M (median) | solve ms (median) | max |Δ| vs cold (s) | not converged in 2000 |
|---|---|---|---|---|---|
| cold (MAX_COST) | 99 | 3.82 | 98.5 | 0.0000 | 0/50 |
| warm: true θ-min field | 99 | 5.64 | 140.4 | 20.1861 | 0/50 |
| warm: U-Net field | 130 | 7.11 | 148.9 | 20.1861 | 8/50 |

読み方: 真の θ 最小場から始めても cold より遅く、U-Net の場からは 8/50 が収束しない。収束したものも真値から最大 20 s ずれる。原因は 2D 場を 60 θ に複製すると 59/60 の状態が楽観的すぎる値になり、値を上げる方向の伝播がゴールから全域にやり直しになること。楽観的な初期値では打ち切り付きの Bellman 更新が真の固定点に戻らない場合もある。warm start を効かせるには 3D（x, y, θ）で楽観的でない場が要り、2D の CNN では役に立たない。

次の候補: CNN の粗場を warm start にして `vi_lib` の `resweep` で厳密解まで持っていく版。
